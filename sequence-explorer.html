Editing the alignment

Tick rows in the alignment to act on them. Every edit is undoable.

Arrange ↑↓Moves the ticked rows. With a project selected the new order is saved; under All it lasts for the session.
ConsensusBuilt from All rows, only the Some ticked ones, or hidden with None.
ColourAll bases, only those that Some differ from the consensus, or None for black and white.
CodeShow DNA, or the protein for the template's coding regions.
A C G T N –Overwrites the selected bases.
Insert / DeleteAdds or removes a column, shifting everything downstream.
Reverse / ComplementApplies to the ticked rows.
UndoUp to 250 steps. Ctrl/Cmd+Z works too.

The alignment

  • Click a base to put the cursor there; shift-click or shift+arrows to extend a selection.
  • Drag the edge of the name column to make it wider or narrower. Names stay pinned when you scroll.
  • Click a primer arrow to use it as one end of the PCR product; click it again to release it. One primer on its own still shows where it matches — two facing primers draw the amplicon between them.

Editing an entry

TypeForward, Reverse, or Sequence. Choosing Reference makes that sequence the template's coordinate anchor. Primer positions and coding regions are recalculated so they stay on the same alignment columns — if the new reference has a different ungapped length the numbers shift, but nothing moves relative to the alignment. The old reference is kept as an ordinary sequence.
PositionA primer's 3′ binding site. Leave it blank and it's found for you when you save.
AlignFor a primer, finds where it best matches the template. For a sequence, aligns it to the reference with gaps penalised heavily, since a disagreement is usually a sequencing error rather than a real indel.
LocationRoom, location, and box, with an optional grid for picking the exact position in a box.

Templates & projects

The Edit button beside the template bar creates and renames both.

  • A template is a reference sequence plus its primers and aligned sequences.
  • A project is a grouping inside one template. Anything can belong to several projects at once, and sit in a different order in each.
  • Renaming a project updates every entry that belongs to it.

Google Sheet structure

Only needed if you're setting up or repairing the sheet by hand — the app manages all of this for you.

One tab. Every row — template, primer, or sequence — uses the same columns. The Apps Script returns it as a JSON array of row objects. A row's Type decides what it is, and Template is the group key that ties a reference, its primers, and its aligned sequences together.

ColumnMeaning
TemplateGroup key (e.g. CYTB). Shared by the reference and all of its primers/sequences.
Typetemplate (the reference / coordinate anchor), sequence (a sequence to align), or forward / reverse (a primer). Older sheets using linear/circular still load as sequences.
FeatureFor a template: coding regions as comma-separated 1-based pairs, e.g. 101-702, 705-887. For a primer: the 1-based 3′ binding position (a single number); the 5′ end and span follow from Type + length. Blank for plain sequences.
VendorOrdering info incl. catalogue number, optional (primers).
NameDisplay name (reference title, arrow label, or alignment row label).
Sequence5′→3′ (A/C/G/T/N). For sequences, pre-aligned to the template's coordinates — same length as the reference, - for gaps; position n = template position n. For primers, the oligo as ordered.
AccessionGenBank / database accession, optional.
ProjectComma-separated project names — a grouping within a template. A row can belong to several projects at once. Each name can optionally end with a bracketed position — Barcoding [S2] for a sequence, Barcoding [P4] for a primer — set by the Arrange buttons and used to order that row within that one project; a row can hold a different position in each project it belongs to. On a template row this column instead lists the projects that exist for that template (never with a position).
Organism · Population · SampleSource metadata, optional (Sample is the specimen / voucher ID).
DateFree-form date, optional (primers and sequences — e.g. ordered, received, or sequenced; whatever fits your workflow).
NotesFree text.
Room · Location1 · Location2 · Box1 · Cell · GridXYPhysical storage, optional (same model as Inventory Explorer).

Tm is always computed from a primer's sequence — there is no Tm column. Coding regions and primer 3′ sites are stored in template coordinates, so adding a sequence with an insertion never renumbers them. Sequences are assumed pre-aligned (no in-browser MSA yet).
